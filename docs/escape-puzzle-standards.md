# 《모여 방탈출》 퍼즐 제작 기준

> EP.01 이후의 모든 에피소드 및 기존 퍼즐 개편에 적용. 본 문서는 제작 원칙만 공개하며, 실제 퍼즐의 정답·해법·내부 판정 상태는 포함하지 않는다.

## 제작 기준 문서 체계

이 저장소의 《모여 방탈출》 에피소드 및 퍼즐 제작 시 다음 **세 문서를 함께 확인하고 적용**한다. 첫째와 둘째는 사용자가 제공한 별개의 프롬프트이며, 서로 합치거나 한쪽 내용을 생략하지 않는다.

1. **[공통 퍼즐 제작 마스터 프롬프트 v2.0 — 원본 18장](escape-master-prompt-v2-original.md)**: 전체 에피소드의 스토리·공간·퍼즐 유형·의존성·장치·테스트·실제 구현 체계. 원문을 보존한다.
2. **[퍼즐 제작 및 개선 통합 프롬프트 — 기본 13개 항목 및 제14~18절 추가 기준](escape-puzzle-design-improvement-prompt.md)**: 풀이법 직접 설명 금지, 관찰 중심 문구, 단서 간 연결, 4단계 힌트, 개선 프로세스, 제작자/플레이어 콘텐츠 분리 등 퍼즐 UX의 품질 기준.
3. **현재 문서(escape-puzzle-standards.md)**: 두 프롬프트를 실제 작업에 적용할 때의 공통 운영 규칙과 충돌 조정 기준.

### 적용 우선순위

- 기본적으로 두 사용자 제공 프롬프트의 내용을 **모두 적용**한다. 한 문서의 규칙을 다른 문서가 언급하지 않는다는 이유로 생략하지 않는다.
- 규정에 차이가 있으면 **풀이법을 미리 알려주지 않는 원칙, 관찰 사실 중심의 플레이어 표현, 합리적인 단서, 접근성**을 우선한다.
- **힌트는 최근 확정한 4단계 규칙을 적용**한다. 원본 마스터 프롬프트 제11장의 '3단계 힌트 + 선택적 정답 확인'은 운영상 '관찰 → 연결 → 방향 → 명시적 정답·해설'의 네 단계로 구현한다.
- 별도의 난이도 모드를 만들지 않고, 하나의 에피소드 안에서 다양한 난이도와 풀이 방식이 나타나도록 조절한다.
- 사용자 요청 없이 제작자용 정답·해설을 공개 게임 화면에 표시하지 않는다.
- 참고 자료가 실제로 확인되지 않았다면 확인했다고 주장하지 않는다.
- **단순 문장 삭제는 개선이 아니다.** 설명을 제거한 자리에는 관찰과 조작을 통해 규칙을 합리적으로 추론할 수 있는 실제 단서가 필요하다.
- 제작 문서는 제작자 참고용이며, 플레이어가 볼 수 있는 게임 화면에 정답을 노출하라는 뜻이 아니다.

## 핵심 원칙

- **설명하지 말고 발견하게 한다.** 관찰 가능한 사실, 사물의 외형, 조작 결과만 플레이어에게 제공한다.
- 규칙을 텍스트로 알려 주거나 문제 표면에서 정답을 암시하지 않는다. 그렇다고 근거 없는 억측이나 모든 배경의 무작위 클릭을 강요하지 않는다.
- 주요 퍼즐은 탐색 → 발견 → 관찰 → 가설 → 조작·실험 → 해결 → 공간 또는 서사 변화를 지향한다.
- 문제를 어렵게 만들기 위해 단서 연결의 근거까지 제거하지 않는다. 단서를 제거한다면 다른 관찰·조작을 통해 합리적으로 복원한다.
- 클릭 가능한 사물은 키보드/모바일에서도 조사 가능해야 한다. 영구 원형 표시는 피하며, 상호작용 피드백은 작고 비강제적인 형태로 둔다.
- 하나의 에피소드에서는 회전, 중첩, 물리 장치, 빛, 경로, 소리, 패턴, 논리, 서사적 추리 등 풀이 메커니즘이 과하게 반복되지 않게 한다.
- 입력 코드/비밀번호 의존도를 낮추고 오브젝트 조작과 그 결과를 중심에 둔다.

## 비핵심 오브젝트와 즉시 시간 가산

상세한 규칙은 **[퍼즐 제작 및 개선 통합 프롬프트 제14절](escape-puzzle-design-improvement-prompt.md#14-비핵심-오브젝트와-선택적-탐색--정답만-반짝이는-방-금지)**에 따른다.

- 정답에 필요한 물건만 빛나거나 클릭 가능하게 만들지 않는다. 자연스러운 생활 소품과 비핵심 조사 대상에도 동일한 상호작용 체계를 적용한다.
- **탐색 편의를 위한 6px 내외의 아주 희미한 점은 선택적으로 표시할 수 있다.** 미해결 핵심 퍼즐과 일반 소품은 **완전히 동일한 점 스타일**을 적용하고, 조사한 사물은 점을 더 희미하게 처리한다. 표시를 끄는 버튼을 제공하고 선택을 저장한다. 큰 반투명 원·후광·풀이 대상 강조는 금지한다. 보이지 않는 클릭 영역은 데스크톱 약 40px, 터치 화면 약 48px로 설정하되 사물끼리 겹치면 위치 또는 크기를 조정한다. **마우스 호버 중에는 커서·툴팁·빛·색상 변화를 표시하지 않는다.** 장면과 핫스폿은 동일한 기본 커서를 사용하며, 키보드 포커스 표시와 직접 요청한 탐험 추천의 일시적 피드백은 유지한다.
- 선택적 심화 조사에는 행동별로 예상 소요 시간 **+5초(짧은 동작) / +10초(일반 조사) / +15초(깊은 수색)** 중 하나를 명시하여 게임 타이머에 즉시 가산한다. 실제 대기나 카운트다운은 만들지 않는다.
- 조작 반응은 즉시 표시하고, 가산된 탐험 시간은 현재 타이머·저장 데이터·재접속·최종 기록에서 일관되게 유지한다.
- 저장된 옛 세이브에서 이미 더해진 +10초는 소급 변경하지 않는다. 완료된 행동의 재확인에는 시간이 추가되지 않고, 새 행동만 지정된 시간을 더한다.
- 시간 가산은 무한 반복되지 않도록 조사 단계를 저장한다. 필수 단서 확인은 시간 벌칙의 대상이 아니다.
- 비핵심 상호작용은 공간의 생동감을 높이는 장치이지, 무작위 클릭을 강제하거나 지루함을 만드는 인위적 시간 끌기가 아니다.

## 완성 일러스트의 가구·부분 오브젝트 전수감사

**[통합 제작 프롬프트 제18절](escape-puzzle-design-improvement-prompt.md)**을 필수 적용한다.

EP.01에서는 **[네 방의 실제 오브젝트 감사표](escape-ep01-object-audit.md)**를 함께 유지한다. 신규 소품 추가/일러스트 교체 시 감사표·좌표·핫스폿·반응을 동시 수정한다.

- 플레이어가 “탁자에는 종이, 종, 천구의가 따로 있잖아?”라고 지적하기 전에 완성 이미지의 각 **물체와 의미 있는 세부 부품**을 전수 조사한다. 가구 단위로 하나만 클릭 가능하게 만들지 않는다.
- 각 방에서 눈에 보이는 사물을 **핵심 / 보조 / 낚시 / 비활성 장식**으로 분류한다. 낚시에는 짧은 재미있는 반응과 선택적 조작을 주되 필수 퍼즐을 막거나 거짓 정답을 유도하지 않는다.
- 각 아이템에 실제 그림 속 조작 위치, 첫 조사, 추가 행동, **행동별 +5/+10/+15초**, 저장·모바일 검증 정보를 기록한다. 비활성 장식은 합리적 이유 없이 늘리지 않는다.
- 종이·액자·서랍손잡이·천구의·등잔 유리·화분·기계 바퀴처럼 **부분 오브젝트는 독립적인 조사 후보**로 검토한다.
- 완성 이미지를 확인한 좌표표로 개발하고, 좌표·히트박스 겹침 및 모든 첫 조사·심화 조사·실패/성공 반응을 테스트한다. 사용자 개별 지적에만 대응하는 식의 수동 개발은 금지한다.
- 새로운 게임 스크립트나 에셋 파일을 추가했다면 **정식 `/escape/` 경로뿐 아니라 맛보기 `/taste/escape/`가 해당 파일을 제공하는지 `server.js`의 `ESCAPE_TASTE_ASSETS` 허용 목록까지 확인한다.** 코드를 추가했어도 서버에서 404가 나면 실제 구현이 아니다.

## 핫스폿의 위치 — 사물의 중심이 아닌 실제 조작 부분

- **문과 출입구는 문짝 중앙이 아니라 손잡이·문고리·걸쇠·열쇠 구멍에 표시**한다. 서랍은 손잡이, 종은 종 몸체/타격부, 등잔은 덮개나 심지, 피아노는 건반, 책은 책등, 꽃은 꽃이나 화분 유리에 표시한다.
- **모든 위치는 실제 해당 방 일러스트를 눈으로 확인하여 설정한다.** 그림에서 어림짐작하거나 다른 방의 좌표, 오래된 3D 모델의 좌표를 재사용하지 않는다.
- 작은 점(약 6px)과 보이지 않는 클릭 판정(hitbox)의 중심이 **같은 조작 지점**을 가리키도록 배치한다. 점은 정확해야 하지만 터치 범위는 적당히 넓혀 접근성을 확보한다.
- 확대/드래그/시점 이동에서도 점과 히트박스가 그림의 해당 사물을 함께 따라가야 한다. 방별 독립 좌표표를 사용한다.
- **그림에 없는 문이나 물건을 빈 벽·바닥·전혀 다른 사물 위에 점으로 표시하지 않는다.** 그런 이동은 별도 방 이동 UI에서 제공하거나, 실제로 그린 뒤에야 장면 핫스폿으로 만든다.
- 배포 전 방별 실제 일러스트 위에 좌표와 이름을 겹쳐 출력한 **앵커 확인용 시안**을 보고 문 손잡이, 서랍 손잡이, 음표/악기, 일러스트와 코드의 내용이 맞는지 확인한다.
- 완료 상태·정답 여부에 따라 마커의 위치·밝기·크기를 달리하여 퍼즐의 중요도를 누설하지 않는다. 조사 완료에 따라 동일하게 흐려지는 효과는 허용한다.
- 위치를 수정해도 기존 사물 ID, 저장 데이터, 퍼즐 성공 판정 및 방 이동 경로는 유지한다.

## 생활 소품의 전면 상호작용과 선택형 미니퍼즐

세부 제작 규칙은 **[퍼즐 제작 및 개선 통합 프롬프트 제15절](escape-puzzle-design-improvement-prompt.md)**을 필수로 참고한다.

- **눈에 보이는 종·등잔·화분·꽃병·책·의자·창문 등 합리적으로 만져볼 만한 사물은 가능한 한 조사 가능**하게 만든다. 배경의 모든 픽셀을 무작위 클릭하게 만들라는 뜻은 아니다.
- 조사만 하고 끝내지 않고 **'종 쳐보기', '등잔에 손 넣어보기', '화분 파보기', '책 뒤집어 보기'** 같은 물건별 고유 행동을 준비한다. 행동 시 즉시 자연스러운 대사, 작은 움직임, 소리, 미로의 반응 등이 나타나야 한다.
- 사소한 사물에도 **짧은 선택형 미니퍼즐**을 넣을 수 있다. 예를 들어 종 옆의 오래된 악보를 보고 3~5음을 연주하면 **"잘했어요!"**라고 반응하되, 본편 필수 퍼즐·인장·문을 해금하지는 않는다.
- 등잔에 손을 넣으면 **"아이쿠, 너무 뜨거워요!"**처럼 즉각적인 반응을 제공한다. 실제 피해나 진행 불가능한 상태를 만들지 않는다.
- 플레이어가 원하는 만큼 소품을 조사할 수 있지만, **모든 소품을 퍼즐로 만들지 않는다**. 짧은 환경 반응, 재치 있는 대사, 선택형 미니퍼즐을 적절히 섞는다.
- 핵심 퍼즐과 구별하되 **필수 대상만 시각적으로 강조하거나 커서·호버로 드러내지 않는다**. 키보드 포커스 안내와 직접 요청한 탐험 추천은 기존 접근성 규칙에 따른다.
- 작은 악보·종소리 미니게임은 본편의 기계식 피아노와 다른 경험을 제공해야 한다. 음소거 환경에도 시각적인 음표·박자 피드백을 제공한다.
- 선택적인 추가 조사에만 **+5초/+10초/+15초의 활동별 게임 내부 시간**을 적용한다. 종을 한 번 칠 때마다 별도 시간을 부과하지 않는다.
- 조사 상태, 추가 행동 결과, 선택형 미니퍼즐 완료 기록은 저장·복원되도록 하고, 기존 에피소드 진행과 엔딩을 방해하지 않는다.

## 카메라·UI·미로 연출 및 시네마틱 피드백

**[퍼즐 제작 및 개선 통합 프롬프트 제16절](escape-puzzle-design-improvement-prompt.md)**을 따른다. 이미 구현된 2.5D 이동·줌 및 조작형 퍼즐을 중복 만들지 말고, 실제 부족한 요소(아이템 조합·스크랩북·미로 표정·환경 애니메이션·핵심 장면 연출)를 보완한다. 네 방의 색감과 UI를 통일하며 저장·엔딩을 유지한다. 이전의 '호버 시 강조' 제안과 충돌하면 최근 확정된 **마우스 호버/커서 무반응** 규칙을 우선한다.

## 필수 단서에도 동일한 조사 비용과 분산 단서 적용

**[통합 제작 프롬프트 제19절](escape-puzzle-design-improvement-prompt.md)**을 적용한다.

- 핵심 퍼즐 물체만 첫 클릭에 전체 단서·조작판이 즉시 열리고, 일반 낚시 물체에서만 +5초/+10초/+15초를 쓰게 만드는 **차별적 시간 구조를 금지한다.**
- 모든 물체의 첫 외관 관찰은 무료. **핵심 물체도 직접 열고·들추고·확대하고·안쪽을 뒤지는 실제 심화 행동에는 사물의 성격에 따라 5·10·15초를 한 번 부과**한다.
- 건반 하나 누르기, 거울 한 번 돌리기, 수문 한 번 이동처럼 퍼즐을 실제 조작하는 매 입력마다 시간을 반복해서 부과하지 않는다. 완료한 조사와 이전 세이브는 소급 청구하지 않는다.
- 중요한 퍼즐은 **관찰 가능한 서로 다른 장소나 물건의 2~3가지 단서**를 결합해 이해하도록 만든다. 한 장의 기록지·조작판에 정답 조건을 전부 보여 주지 않는다.
- 단서 분산은 **실제 정보 분산**이어야 한다. 단지 'A와 B를 클릭했는가'라는 숨은 플래그로 정답을 봉쇄하는 인위적 게이트는 만들지 않는다.
- 세부 사례·검증 항목은 제19절을 기준으로 하며, EP.01의 실제 적용 상태는 [오브젝트 감사표](escape-ep01-object-audit.md)에 기록한다.

## 단서 구성

- 주요 퍼즐에는 서로 다른 물체 또는 공간의 **독립적 관찰 단서 두 가지 이상**을 권장한다.
- 자연스러운 연결 근거를 주되, 플레이어 대신 연결을 해석하지 않는다.
- 정답 발견 전에 필요한 정보가 실제 플레이 가능한 공간에서 확인 가능해야 한다. 선택 수집품을 필수 진행의 유일 단서로 사용하지 않는다.
- 실패 피드백은 관찰 가능한 물리 반응으로 표현한다. 시스템이 “A를 B에 맞추세요”라고 설명하지 않는다.
- 필수 퍼즐을 해결하면 다음 공간 해금, 환경 변화, 인물 기억의 변화 등 실제 보상이 있어야 한다.

## 힌트: 요청한 경우에만 4단계

1. 관찰: 놓친 물건이나 특성을 상기시킨다.
2. 연결: 서로 관련된 단서 두 가지의 관계를 암시한다.
3. 방향: 원리 또는 조작 방향을 설명하되 정확한 정답이나 순서를 제공하지 않는다.
4. 해설: 플레이어가 **명시적으로 '정답과 해설 보기'**를 선택하면 전부 공개한다.

- 대기 시간이나 실패 횟수를 이유로 힌트를 자동 공개하지 않는다.
- 4단계 이전에 정확한 숫자·배치·조합·순서가 노출되지 않았는지 별도로 점검한다.

## 제작 분리

- **제작자 설계서**는 정답, 단계별 논리, 단서 의존 그래프, 판정 조건, 유일성 검증, 임의 대입 가능성, 예외처리, 저장 호환성을 포함한다.
- **플레이어 표시 문구**는 외형, 조사, 조작 반응, 실패/성공 연출만 포함하며 정답을 저장소의 공개 웹 페이지에 직접 노출하지 않는다.
- 공개 게임 사이트와 같은 경로에 제작자 전용 정답 문서를 배포하지 않는다. 이 저장소는 공개 저장소이므로 스포일러가 포함된 문서는 별도 비공개 저장소 또는 제작자 로컬 파일로 관리한다.

## 난이도와 품질

- 쉬운 퍼즐: 관찰과 작은 실험만으로 가능.
- 중간 퍼즐: 독립 단서 2개 이상을 결합.
- 어려운 퍼즐: 여러 단서 해석과 재시도 가능한 장치 조작.
- 최종 퍼즐: 이전 공간, 사건의 진실, 획득한 물건을 의미 있게 통합.

각 퍼즐에 대해 ①발견 ②규칙의 자가 추론 ③단서 연결 ④의미 있는 조작 ⑤정답의 유일성 ⑥찍기 방지 ⑦불필요한 클릭 최소화 ⑧메커니즘 다양성 ⑨서사 통합 ⑩성공 보상을 각각 1~5점으로 평가하고, 3점 이하의 항목은 개선안을 명시한다. 프로토타입 자가평가는 초심자 블라인드 플레이 검증을 대체할 수 없다.

## 수정 및 검증 순서

1. 현재 화면에서 풀이법을 설명하는 대사·단서·UI를 수집한다.
2. 플레이어가 깨달을 원리와 필요한 증거를 식별한다.
3. 근거가 있는 단서를 공간에 배치하고 조작 가능한 상태를 추가한다.
4. 게임 엔진·결과 보상·서사 연결을 업데이트한다.
5. 모든 정답 경로가 성립하는지와 가능한 경우의 유일성을 검증한다.
6. 잘못된 조합이 통과하지 않도록 부정 테스트를 진행한다.
7. 로컬 저장, 이전 진행 기록, 모바일/키보드 조작을 점검한다.
8. 제작자 전용 설계와 플레이어 문구를 분리해 검토한다.
9. 실제 초심자가 힌트 없이 풀이하는 관찰 테스트를 진행한다.
