# 《모여 방탈출》 퍼즐 제작 기준

> EP.01 이후의 모든 에피소드 및 기존 퍼즐 개편에 적용. 본 문서는 제작 원칙만 공개하며, 실제 퍼즐의 정답·해법·내부 판정 상태는 포함하지 않는다.

## 제작 기준 문서 체계

이 저장소의 《모여 방탈출》 에피소드 및 퍼즐 제작 시 다음 **세 문서를 함께 확인하고 적용**한다. 첫째와 둘째는 사용자가 제공한 별개의 프롬프트이며, 서로 합치거나 한쪽 내용을 생략하지 않는다.

1. **[공통 퍼즐 제작 마스터 프롬프트 v2.0 — 원본 18장](escape-master-prompt-v2-original.md)**: 전체 에피소드의 스토리·공간·퍼즐 유형·의존성·장치·테스트·실제 구현 체계. 원문을 보존한다.
2. **[퍼즐 제작 및 개선 통합 프롬프트 — 13개 항목](escape-puzzle-design-improvement-prompt.md)**: 풀이법 직접 설명 금지, 관찰 중심 문구, 단서 간 연결, 4단계 힌트, 개선 프로세스, 제작자/플레이어 콘텐츠 분리 등 퍼즐 UX의 품질 기준.
3. **현재 문서(escape-puzzle-standards.md)**: 두 프롬프트를 실제 작업에 적용할 때의 공통 운영 규칙과 충돌 조정 기준.

### 적용 우선순위

- 기본적으로 두 사용자 제공 프롬프트의 내용을 **모두 적용**한다. 한 문서의 규칙을 다른 문서가 언급하지 않는다는 이유로 생략하지 않는다.
- 규정에 차이가 있으면 **풀이법을 미리 알려주지 않는 원칙, 관찰 사실 중심의 플레이어 표현, 합리적인 단서, 접근성**을 우선한다.
- **힌트는 최근 확정한 4단계 규칙을 적용**한다. 원본 마스터 프롬프트 제11장의 '3단계 힌트 + 선택적 정답 확인'은 운영상 '관찰 → 연결 → 방향 → 명시적 정답·해설'의 네 단계로 구현한다.
- 별도의 난이도 모드를 만들지 않고, 하나의 에피소드 안에서 다양한 난이도와 풀이 방식이 나타나도록 조절한다.
- 사용자 요청 없이 제작자용 정답·해설을 공개 게임 화면에 표시하지 않는다.
- 참고 자료가 실제로 확인되지 않았다면 확인했다고 주장하지 않는다.
- **단순 문장 삭제는 개선이 아니다.** 설명을 제거한 자리에는 관찰과 조작을 통해 규칙을 합리적으로 추론할 수 있는 실제 단서가 필요하다.
- 제작 문서는 제작자 참고용이며, 플레이어가 볼 수 있는 게임 화면에 정답을 노출하라는 뜻이 아니다.

## 핵심 원칙

- **설명하지 말고 발견하게 한다.** 관찰 가능한 사실, 사물의 외형, 조작 결과만 플레이어에게 제공한다.
- 규칙을 텍스트로 알려 주거나 문제 표면에서 정답을 암시하지 않는다. 그렇다고 근거 없는 억측이나 모든 배경의 무작위 클릭을 강요하지 않는다.
- 주요 퍼즐은 탐색 → 발견 → 관찰 → 가설 → 조작·실험 → 해결 → 공간 또는 서사 변화를 지향한다.
- 문제를 어렵게 만들기 위해 단서 연결의 근거까지 제거하지 않는다. 단서를 제거한다면 다른 관찰·조작을 통해 합리적으로 복원한다.
- 클릭 가능한 사물은 키보드/모바일에서도 조사 가능해야 한다. 영구 원형 표시는 피하며, 상호작용 피드백은 작고 비강제적인 형태로 둔다.
- 하나의 에피소드에서는 회전, 중첩, 물리 장치, 빛, 경로, 소리, 패턴, 논리, 서사적 추리 등 풀이 메커니즘이 과하게 반복되지 않게 한다.
- 입력 코드/비밀번호 의존도를 낮추고 오브젝트 조작과 그 결과를 중심에 둔다.

## 비핵심 오브젝트와 즉시 시간 가산

상세한 규칙은 **[퍼즐 제작 및 개선 통합 프롬프트 제14절](escape-puzzle-design-improvement-prompt.md#14-비핵심-오브젝트와-선택적-탐색--정답만-반짝이는-방-금지)**에 따른다.

- 정답에 필요한 물건만 빛나거나 클릭 가능하게 만들지 않는다. 자연스러운 생활 소품과 비핵심 조사 대상에도 동일한 상호작용 체계를 적용한다.
- **핫스폿의 반투명 동그라미와 빛 점은 평상시에 완전히 숨긴다.** 보이지 않는 클릭 영역은 데스크톱 약 40px, 터치 화면 약 48px로 설정하되 사물끼리 겹치면 위치 또는 크기를 조정한다. **마우스 호버 중에도 커서·툴팁·빛·색상 변화를 절대 표시하지 않는다.** 장면과 핫스폿은 동일한 기본 커서를 사용한다. 다만 키보드 포커스 접근성 표시와 플레이어가 직접 요청한 탐험 추천의 일시적 피드백은 유지한다.
- 선택적 심화 조사(예: 파보기, 더 살펴보기)에 **게임 타이머 +10초**를 즉시 가산할 수 있다. 실제 대기시간이나 카운트다운을 만들지 않는다.
- 조작 반응은 즉시 표시하고, 가산된 탐험 시간은 현재 타이머·저장 데이터·재접속·최종 기록에서 일관되게 유지한다.
- 시간 가산은 무한 반복되지 않도록 조사 단계를 저장한다. 필수 단서 확인은 시간 벌칙의 대상이 아니다.
- 비핵심 상호작용은 공간의 생동감을 높이는 장치이지, 무작위 클릭을 강제하거나 지루함을 만드는 인위적 시간 끌기가 아니다.

## 단서 구성

- 주요 퍼즐에는 서로 다른 물체 또는 공간의 **독립적 관찰 단서 두 가지 이상**을 권장한다.
- 자연스러운 연결 근거를 주되, 플레이어 대신 연결을 해석하지 않는다.
- 정답 발견 전에 필요한 정보가 실제 플레이 가능한 공간에서 확인 가능해야 한다. 선택 수집품을 필수 진행의 유일 단서로 사용하지 않는다.
- 실패 피드백은 관찰 가능한 물리 반응으로 표현한다. 시스템이 “A를 B에 맞추세요”라고 설명하지 않는다.
- 필수 퍼즐을 해결하면 다음 공간 해금, 환경 변화, 인물 기억의 변화 등 실제 보상이 있어야 한다.

## 힌트: 요청한 경우에만 4단계

1. 관찰: 놓친 물건이나 특성을 상기시킨다.
2. 연결: 서로 관련된 단서 두 가지의 관계를 암시한다.
3. 방향: 원리 또는 조작 방향을 설명하되 정확한 정답이나 순서를 제공하지 않는다.
4. 해설: 플레이어가 **명시적으로 '정답과 해설 보기'**를 선택하면 전부 공개한다.

- 대기 시간이나 실패 횟수를 이유로 힌트를 자동 공개하지 않는다.
- 4단계 이전에 정확한 숫자·배치·조합·순서가 노출되지 않았는지 별도로 점검한다.

## 제작 분리

- **제작자 설계서**는 정답, 단계별 논리, 단서 의존 그래프, 판정 조건, 유일성 검증, 임의 대입 가능성, 예외처리, 저장 호환성을 포함한다.
- **플레이어 표시 문구**는 외형, 조사, 조작 반응, 실패/성공 연출만 포함하며 정답을 저장소의 공개 웹 페이지에 직접 노출하지 않는다.
- 공개 게임 사이트와 같은 경로에 제작자 전용 정답 문서를 배포하지 않는다. 이 저장소는 공개 저장소이므로 스포일러가 포함된 문서는 별도 비공개 저장소 또는 제작자 로컬 파일로 관리한다.

## 난이도와 품질

- 쉬운 퍼즐: 관찰과 작은 실험만으로 가능.
- 중간 퍼즐: 독립 단서 2개 이상을 결합.
- 어려운 퍼즐: 여러 단서 해석과 재시도 가능한 장치 조작.
- 최종 퍼즐: 이전 공간, 사건의 진실, 획득한 물건을 의미 있게 통합.

각 퍼즐에 대해 ①발견 ②규칙의 자가 추론 ③단서 연결 ④의미 있는 조작 ⑤정답의 유일성 ⑥찍기 방지 ⑦불필요한 클릭 최소화 ⑧메커니즘 다양성 ⑨서사 통합 ⑩성공 보상을 각각 1~5점으로 평가하고, 3점 이하의 항목은 개선안을 명시한다. 프로토타입 자가평가는 초심자 블라인드 플레이 검증을 대체할 수 없다.

## 수정 및 검증 순서

1. 현재 화면에서 풀이법을 설명하는 대사·단서·UI를 수집한다.
2. 플레이어가 깨달을 원리와 필요한 증거를 식별한다.
3. 근거가 있는 단서를 공간에 배치하고 조작 가능한 상태를 추가한다.
4. 게임 엔진·결과 보상·서사 연결을 업데이트한다.
5. 모든 정답 경로가 성립하는지와 가능한 경우의 유일성을 검증한다.
6. 잘못된 조합이 통과하지 않도록 부정 테스트를 진행한다.
7. 로컬 저장, 이전 진행 기록, 모바일/키보드 조작을 점검한다.
8. 제작자 전용 설계와 플레이어 문구를 분리해 검토한다.
9. 실제 초심자가 힌트 없이 풀이하는 관찰 테스트를 진행한다.
